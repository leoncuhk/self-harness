# FAB v2 题目与规则深度梳理

> 基于 `finance-agent-v2/data/public.csv`（27 道公开题 + 完整官方 rubric）与评测源码的一手分析。
> 事实基线：全量 927 题 = 27 公开 + 450 验证集（授权）+ 450 测试集（永不公开）。官方榜只看测试集。

## 一、题目全景（27 题样本推断全集结构）

九大类别，公开样本中每类恰好 3 题，推断全集为均衡抽样：

| 类别 | 题均检查点 | 题均 dealbreaker | 平均专家用时 | 考查内核 |
|---|---|---|---|---|
| Financial Modeling | 7.0 | 2.7 | **81 min** | DCF/LBO/永续增长三选一，给定假设求 EV、IRR、MOIC、每股价值 |
| Disclosure Analysis | 11.7 | 3.7 | **70 min** | 10-K 附注深挖：PPA 变动、减值明细、重组负债 roll-forward、折旧年限变更 |
| Comparables | 9.0 | 3.0 | 43 min | P/B、D/E、EV/EBITDA、FCCR 等估值比率，跨公司对比+排名结论 |
| General Qualitative | 7.7 | 1.7 | 43 min | 风险因素/竞争披露的忠实转述，逐点覆盖 |
| Adjustments | 12.3 | 4.3 | 38 min | GAAP→Adjusted EBITDA 桥逐行还原、毛利率变动归因与正常化 |
| Market Analysis | 9.3 | 3.7 | 38 min | 事件窗口股价回报（价格工具）+ 财务增速排名对比 |
| Precedents | 9.3 | 1.7 | 28 min | 并购交易：溢价、协同效应、TV/Revenue、TV/EBITDA 倍数 |
| Earnings Analysis | 6.7 | 4.0 | 28 min | 指引 midpoint 推导、beat/miss %、capex 强度对比 |
| General Quantitative | 6.7 | 1.7 | **20 min** | CAGR、DIO、EBITDAR 等标准财务计算 |

关键观察：
1. **检查点密度差异巨大**：定性题靠"逐点覆盖"，建模题靠"一条数值链全对"。专家用时与检查点数不完全相关——Disclosure 一题 120 分钟（PFE Seagen PPA+减值），因为它要求跨年报、跨附注交叉取数。
2. **数值精度要求到 0.01**：rubric 中如 `32.82%`、`1,715 bps`、`$6,300.07 million`、`17.27%`、`2.22x`。负数用括号 `(2.79%)` 表示。
3. **排名/比较类问题几乎都有 must_pass 结论项**：答案必须明确给出"谁更高/排名顺序/是否一致"。

## 二、评分规则（从 rubric 结构反推官方算法）

每个检查点结构：`{criteria: 自然语言判据, severity: 1.0|2.0|3.0, category?: "must_pass"}`

统计（27 题）：
- 检查点总数 239，其中 **must_pass（dealbreaker）79 个，占 33%**
- 每题 dealbreaker 数量：最少 1 个，最多 7 个，均值 2.9
- severity 分布：1.0 × 170，2.0 × 60，3.0 × 9

评分公式（Partial Credit，主指标）：
```
若任一 must_pass 检查点未通过 → 该题 0 分
否则 → 该题得分 = Σ(severity_i × pass_i) / Σ(severity_i)
```

All-Pass（副指标）：全部检查点通过才算 100%，否则 0 分。

三个推论（决定优化方向的优先级排序）：
1. **dealbreaker 是第一杀手**。答对 8/10 个检查点但挂 1 个 must_pass = 0 分。反之，先保 dealbreaker 全对，再捡 severity 高的普通点，是期望得分最大化策略。
2. **数值链条题的 dealbreaker 常是"最终计算结果"**（如 EPAM 的 exit equity value、LMT 的每股价值），中间步骤错→结论错→可能同时挂掉 2-4 个检查点。建模题必须用 calculator 全程算，不允许心算。
3. **结论性表述的措辞要对齐判据**。如"rankings are not the same"、"Conclude that TGT demonstrates stronger fixed charge coverage"——答案里要有明确、无歧义的结论句。

## 三、评测环境硬约束（源码级事实）

来源：`finance_agent/` + `model_library/`（Vals 自研框架，已随仓库装好）

### 3.1 Agent 循环
- 输入 = 固定 SYSTEM_PROMPT + 题目；每题独立运行，限时 2 小时（wall clock 减去重试等待），默认无 turn 上限
- **必须调用 `submit_final_result` 工具才算交卷**；纯文本回复会被注入提示强制继续
- 上下文溢出 → 丢弃最旧历史（`truncate_oldest`），即"失忆"继续——长题要防
- 每个 turn 完整落盘：`logs/finance/<model>/<ts>/turns/turn_NNN/`（query 原文、工具调用与结果、state 快照、历史），复盘素材齐全

### 3.2 六个工具（官方统一提供，不可增删——上榜口径下）
| 工具 | 后端 | 关键细节 |
|---|---|---|
| `edgar_search` | sec-api.io 全文检索 | 只返回 filing 元数据（含 URL），正文要靠 parse_html_page 取 |
| `parse_html_page` | aiohttp + BeautifulSoup | 存入 `state[key]`；sec.gov 429/503 重试耗尽会**终止整题**（RetryExhaustedError） |
| `retrieve_information` | 同一个 LLM | 把 `{{key}}` 替换为文档全文再查询；支持字符区间切片；这是绕开上下文限制的核心机制 |
| `web_search` | Tavily（fast 深度） | 每源只给 1 个摘录块，通常还需 parse 原页面 |
| `price_history` | Tiingo | 返回 CSV 日线；体系提示要求用**未复权**价；指数不覆盖（提示用 FRED）；`MAX_END_DATE=2026-03-01` 封顶 |
| `calculator` | SimpleEval | 仅 `+ - * / ** %` 和 6 个函数；无 `^`、无幂函数简写 |

### 3.3 体系提示中的"考点陷阱"（官方 SYSTEM_PROMPT 已写明的规则）
- 当前日期视为 **2026-03-01**（所有工具的日期上限也被钉死在这里）
- SEC filing 是最权威来源，与其他来源冲突时以 SEC 为准
- 报告口径跟随 filing 的单位（"in millions" 就报 millions）
- 中间过程不四舍五入，最终答案至少 2 位小数
- 股价 2 位小数；来源列表以 JSON 字典收尾

### 3.4 本地 vs 平台（可行性结论）
- **跑题**：`finance-agent` CLI 完全独立于 Vals 平台，本地就能跑任意题目（包括未来的验证集）。平台（suites.json/Test Suite ID）只是他们内部批量调度用。
- **评分**：官方 rubric 判分在 Vals 平台侧执行，不在开源仓库里。但 public.csv 给了 27 题的完整 rubric → **可以自建本地 LLM 裁判近似官方判分**，闭环迭代不需要等平台审批。官方裁判是三模型陪审团（GPT-5.4 / Gemini-3.1-Pro / Claude Sonnet 4.6），本地裁判可用同族模型近似。
- **成本项**：模型 API 费 + Tavily + sec-api + Tiingo 四类 key。每题最长 2 小时、几十个 turn，token 消耗可观。

## 四、从 rubric 反推的"答案格式规范"（拿分必备）

逐条核对 rubric 判据后提炼，agent 的最终提交应遵守：

1. **每个数字给到 2 位小数**，负数写括号或负号均可但要与判据一致的方向
2. **百分比 vs 倍数 vs bps 跟随判据口径**：`(2.79%)`、`1,715 basis points`、`10.91x`、`$419.21`
3. **明确写出比较/排名结论句**："X is higher than Y"、"rank order from highest to lowest is A, B, C, D"、"the rankings are not the same"
4. **中间数值也要报**：很多检查点是中间量（如"average inventory is $22,213.50 million"、"FY2026 D&A is $5,828 million"）——最终提交里要保留完整计算链路的所有关键中间值
5. **定性题逐点覆盖判据关键词**：如 CRWD 题要出现 "Falcon platform AI-native"、"Charlotte AI generative AI security analyst"、"Falcon AIDR"、"adversarial AI" 等原词
6. **来源列表**：结尾附 `{"sources": [...]}` JSON（体系提示要求，也可能被裁判参考）

## 五、九类题的解题模板（从 27 题归纳）

- **定性/披露题**：edgar_search 定位 10-K/10-Q → parse 存储全文 → retrieve_information 分段精读 → 按主题（风险/竞争/AI/减值）逐块抽取 → 汇总成带关键词的逐点答案
- **定量/可比/ precedent 题**：先明确口径（哪个财年、哪个报表、什么调整）→ 取数（多来自 filing 正文或附注）→ calculator 逐步算 → 报全部中间值 → 给比较结论
- **市场分析题**：price_history 取区间收盘价（注意日历日 vs 交易日、复权口径）→ 财报取增速 → 两个排名 → 一致性结论
- **建模题**：逐年列出假设 → 建收入/EBITDA/NWC/CapEx 预测表 → FCFF 折现（exit multiple 或 Gordon）→ EV → equity → 每股/IRR/MOIC。**全程 calculator**，rubric 连 FY2031 收入 $66,585.80M 这种中间值都查
