# FAB v2 迭代作战方案

> 目标：通过持续迭代，在 FAB v2 验证集（450 题）上达到并超越官方榜首水准（Partial Credit ≈ 60.6%，All-Pass ≈ 50.9%，测试集口径）。
> 战场分两条线：**本地闭环**（27 公开题，即日开始）→ **验证集**（授权到位后切换）。

## 一、总路线图

| 阶段 | 内容 | 产出 / 出口条件 |
|---|---|---|
| P0 基础设施（本周） | 本地评分器 + 结果分析脚本 + 失败归因看板 | 一条命令完成"跑题→判分→归因报告" |
| P1 基线（本周） | 用 1-2 个候选模型跑通 27 题，建立基线分 | 基线 Partial Credit / All-Pass + 成本/题 |
| P2 逐类攻坚（2-4 周） | 按九类题型逐类优化，dealbreaker 优先 | 每类 dealbreaker 通过率 ≥ 85% |
| P3 压力与稳定（2 周） | 3 次重复运行测方差、超时题治理、长题防"失忆" | 27 题均值 ± 1 次标准差稳定 |
| P4 验证集切换（授权后） | 同一套流水线跑 450 题，只换数据源 | 验证集得分 vs 官方榜对比报告 |

关键原则：**所有优化以本地判分闭环为准绳，不凭感觉调 prompt。**

## 二、本地评分闭环设计（P0 核心交付）

```
runner ──► finance-agent CLI（官方 harness，不改动跑题逻辑）
   │              │
   │              ▼
   │        logs/<run>/…（每 turn 全量落盘）+ results.json（final_answer）
   ▼
judge ──► 本地评分器（新增，playbook/ 下）
   │      ├─ 数值型判据 → 确定性判分：从 answer 抽取数字，容差判等
   │      │   （绝对 0.01 或相对 0.5%，取宽者——对齐官方 LLM 裁判的模糊度）
   │      └─ 定性型判据 → LLM 裁判：单条判据 + 完整 answer → pass/fail + 证据引用
   ▼
report ──► 归因看板：每题得分、dealbreaker 命中/漏掉清单、按类别汇总、
          与上一轮 diff、token/时长成本
```

设计要点：
1. **判分双轨制**。239 个判据中约 7 成含精确数值（"32.82%"、"$6,300.07 million"），这些用确定性判分避免裁判漂移；纯定性判据（"concludes that…"）用 LLM 裁判。数值判据先跑确定性轨，保证迭代信号的稳定性。
2. **裁判模型固定且独立**。裁判模型与被测模型必须不同家族（官方就是三模型陪审团制）。裁判 prompt 要求输出 `{pass: bool, evidence: "答案原文引用"}`，便于人工抽查裁判质量。
3. **评分器要用 27 题做自校准**：拿"标准答案级"的完美提交（从 rubric 拼出）喂给评分器，必须 27 题全 100%；再拿故意残缺的提交验证 dealbreaker 归零逻辑。
4. **工具层缓存（省钱关键）**。edgar_search / parse_html_page / price_history 按 URL+参数 哈希落盘缓存，重跑同一题时工具结果直接复用——迭代轮次中外部 API 成本降一个数量级（仅限本地迭代；正式计分跑全量真实调用）。
5. **正式计分跑**的口径：无缓存、temperature 与官方一致（默认 1.0）、跑 3 次取均值±标准误，对齐官方协议。

## 三、优化杠杆清单（按预期收益排序）

### 杠杆 1：dealbreaker 命中率（预期收益最大）
- 失败模式 A：**结论句缺失**。优化 SYSTEM_PROMPT 增补"逐判据式作答规范"：比较题必写明确结论句、中间值全报、2 位小数、括号负数、bps/x/％ 口径。（01 文档第四节已整理成规范，直接进 prompt）
- 失败模式 B：**数值链断裂**。强制"每个计算都过 calculator + 在提交中展示完整算式"。
- 失败模式 C：**口径错位**（财年错、复权错、单位错）。在 prompt 中内置"作答前先重述口径清单"的检查步骤。

### 杠杆 2：检索与取证策略
- 10-K/10-Q 定位：优先 edgar_search 用公司 CIK + 表型过滤；一份 10-K 正文常超百万字符，parse 后**必须** retrieve_information 分段抽取（利用字符区间），不要整篇塞 prompt
- 附注深挖题（Disclosure）：教 agent "目录定位法"——先 retrieve 提取 TOC 段定位附注编号，再按区间精读
- 事件窗口题：先用 8-K 定位公告日，再 price_history 取窗口，注意"日历日 vs 下一交易日"规则（rubric 已揭示官方算法：非交易日顺延）

### 杠杆 3：模型与参数选择
- 基线候选（官方榜头部即可参考）：Claude Sonnet 4.5+、GPT-5.x、Gemini 3.x Pro、Kimi K3 等，registry 全支持 `provider/model` 直连
- 待实验变量：temperature（1.0 → 0.2 是否更稳）、max_tokens、reasoning effort（若模型支持）
- **双轨竞赛制**：Track A 固定官方 harness 只换模型（与官方榜严格可比）；Track B 允许改 SYSTEM_PROMPT/编排（上限更高，结论标注口径）。两轨都保留成绩。

### 杠杆 4：长题与超时治理
- Disclosure/Modeling 题专家都要 70-120 分钟，agent 2 小时容易耗尽 → 教 agent "先计划后执行"：第一步先列出取证清单再动手
- 上下文溢出会丢最旧历史 → 关键中间结论要随手写进"工作笔记"（存 state 或复述在对话里），不依赖开头的记忆
- sec.gov 限流会 RetryExhausted 直接判死整题 → prompt 中要求对 sec.gov 的 parse 请求串行、间隔，且优先用 edgar_search 返回的稳定 URL

## 四、迭代节奏与统计纪律

- 每轮 = 27 题全量（并行度 3-5，单轮墙钟约 2-3 小时）→ 判分 → 归因 → 改动 1-2 个变量 → 下一轮
- **一次只改一个杠杆**，归因看板必须能回答"这个改动让哪些判据从 fail 变 pass / pass 变 fail"
- 阶段性正式计分跑（无缓存 × 3 次）作为里程碑成绩，防止在缓存加持下过拟合
- 27 题样本小（每类仅 3 题），单题波动 ±3.7 个百分点 → 看类别趋势而不是总分小数点
- 防过拟合纪律：rubric 只用于判分与归因，**不得**把判据原文硬编码进 prompt；优化必须走"归纳成通用规范 → 验证"的路径

## 五、成本预算（数量级估算）

单题消耗（参考官方 2 小时上限，实际多在 20-60 分钟）：
- 主模型：长题 50-150 turn，输入随历史膨胀，估 0.5-3M token/题 → 模型 API 约 $1-15/题
- 工具：Tavily ~免费额度起步；sec-api 按调用计费；Tiingo 免费档可用
- 27 题一轮：估 $50-300（模型为主）；缓存后迭代轮接近 $0 外部 API
- 450 题验证集一轮 × 3 次：$2.5K-40K 量级（模型选择影响巨大，P1 实测后精算）

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 授权谈判慢/被拒（个人身份） | 本地 27 题闭环先行，不等授权；邮件策略见 03 文档 |
| 本地裁判与官方裁判判分偏差 | 数值判据占 7 成且走确定性轨；定性判据裁判用异家族模型并抽查校准 |
| 在 27 题上过拟合 | 通用规范化改动 + 类别级归因；P4 首轮验证集成绩做"诚实检查" |
| 工具 API 限流/断供 | 多 key 轮换（harness 已支持分号分隔）；正式跑前做容量检查 |
| 单机跑 450×3 轮次太慢 | harness 自带并行度参数；必要时分批断点续跑 |
